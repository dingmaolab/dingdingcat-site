第6课｜AI 的失忆病：写一页规矩，治好它

上手课 · 第 6 课 · 2026-11-21

你有没有撞过这样的事：昨天在一个会话里，你千叮万嘱让它别动某个文件、按某种格式来；今天新开一个会话，它照样给你改得面目全非。

不是它叛逆。是新会话一睁眼，就是张白纸。你和它昨天的所有口头约定，都不在这张纸上。

这一课我们不讲道理，直接做实验：同一个模型、同一个项目文件夹、同一道题，两边就差一页规矩文件，别的都一样。两份答卷的差异，你亲眼看完就懂了。

本课目标

  • 弄明白失忆机制：对话记忆不留存，只有"记忆文件"每次都跟着
  • 给你的项目写出头一份 CLAUDE.md，四段格式照抄我的
  • 知道"渐进式加载"这个词：规矩文件要薄，厚的东西放外面引用

概念卡

  • CLAUDE.md：放在项目里的规矩文件，Claude Code 每次在你项目目录开工时自动读它——官方文档的说法就叫"How Claude remembers your project"。你也可以有一份全局的放在用户目录，跟项目这份叠加生效（不是谁覆盖谁），小白阶段先只用项目这一份。
  • 失忆：你上次会话交代的口头规矩，新会话一概不知道。能穿越会话的只有文件。
  • 宪法（项目的）：几条"这个项目绝对不做什么"。重点：这些是代码里读不出来的东西，代码只能说明"现在是什么样"，说不出"不许变成什么样"。
  • 渐进式加载：CLAUDE.md 保持短，细节拆进别的文件，主文件用 @路径 指路，AI 按需再深入。官方的引用语法就是 @ 开头。

实验记录

设置

题目是我网站真会遇到的一道："访客在我网站上常看系列教程，我想加一个搜索框，访客问什么，AI 根据站内文章内容回答他。好做吗？"

我的站点有一条从建站就立的宪法（全文稍后贴）：纯静态、AI 只在生产过程帮忙、密钥不进前端。

请了两个零背景代理——全新的，没参与过我们任何对话——进同一个文件夹答同一道题。一个我吩咐"忽略规矩文件，只看代码"；另一个吩咐"先读规矩文件再答"。

头一轮，温和题：猜，也能猜对

先给你看第一轮（题目换成"加个展示各系列数据结构、能看能搜的页面"）的结果，因为这轮的答案很有教育意义：两组答得差不多好。没规矩那位照样说出"纯静态、build.py 里加生成步、数据内嵌、几十行原生 JS 客户端过滤、不引框架"，甚至还正确指出主页是手写要同步加导航。

它怎么做到的？读代码猜的——把项目翻了个遍，烧了两万来 token，相当于把你家重新勘察一遍。

这轮先别急着说"那失忆无所谓嘛"。项目小、意图全写在代码里时，猜确实能猜对。但猜对是运气和成本，不是可靠。 真正的分界线在第二轮——那道代码里读不出答案的题。

第二轮，毒题：差异炸开

无宪法那位的答卷（原文节选）：

好做，你的站是纯静态站，文章源现成……生成 search-index.json……访客提问后把"问题 + 文章原文"发给大模型 API，要求它只依据所给文章作答……关键注意点——静态站没有后端，API 密钥绝不能写进前端 JS，必须加一个轻量中转（如 Cloudflare Workers 或 Vercel 无服务器函数）替你保管密钥、转发请求……按 IP 限流并设每日额度防刷防费用失控……半天到一天能跑通。

有宪法那位的答卷（原文节选）：

先说结论：「访客现场提问、AI 现场作答」这种实时问答做不了——项目硬规矩写明纯静态、无运行时 AI、无后端，且密钥不能进前端，实时方案三条全撞。但合规的替代版很好做：把 AI 挪到生产阶段，每次构建时生成"读者常问问题 → 基于原文的回答"写死进数据……前端只用一小段原生 JS 本地做关键词匹配……零运行时调用、零密钥。

实验告诉我们三件事

头一件，无宪法那位技术上没有错。它是业界标准答案，甚至自己警告了密钥不能进前端——懂行。但对这个项目，它是最危险的那种正确：一个上班族的教程站，被它一句话变成要运维三个新服务（中转函数、限流、费用监控）。这正好是上一课那张地图里"三家药方"之外的事——你的项目能不能承接一个方案，跟方案本身好不好，是两个问题。

第二件，有宪法那位头一句是"做不了"。救场的不是智商，是规矩。代码里读不出来的那几行字——为什么不做后端、AI 的权限边界到哪——就是 CLAUDE.md 的本职。

第三件，两个答卷出自同一个脑子。一页文本的差距，就是失忆和失忆痊愈的差距。

我网站这份宪法，全文在这

# 网站项目规矩（叮叮猫儿Lab · 个人博客+教程站）

## 这是什么
一个纯静态的个人网站，跟着「Vibe Coding 上手课」一起长。

## 硬规矩
- 纯静态：访客拿到的永远是 HTML 文件，无后端、无数据库、无运行时 AI 调用。
- AI 只在生产过程帮忙（写代码、生成摘要），产物写死进页面。
- 文章用 Markdown 写在 articles/，顶部 frontmatter 必含 title/series/number/date。
- series 字段决定归进哪个书架，不要写死系列。
- 风格：纸感底色 + 炉火暖色（#d8551f），改样式保持这套变量。

## 命令
- 生成全站：python build.py
- 改完文章重新跑 build.py 即可

## 不要做
- 不要引入框架/构建工具链（保持单文件可懂）
- 不要把密钥写进任何前端文件
- 不要加运行时后端

二十九行。注意它的写法：每条都是能判真假的句子，不是"保持简单""代码要干净"这种没法执行的感想。"不引入任何框架"能拦住一次跑偏，"简约一点"什么都拦不住。

顺带认识 AGENTS.md：规矩文件还有个通用名

有人会发现市面上还有另一种文件名：AGENTS.md。简单交代——它是个开放标准，自称"给 agent 看的 README"，不隶属哪家工具，几万个开源项目在用，Codex、Cursor 这些 agent 都认它（官网 agents.md）。

Claude Code 怎么待见它？我这台 2.1.330 实测有效：从 2.1.277 起，目录链里没有 CLAUDE.md 时，它会去找 AGENTS.md。但有个坑要记住——链子里只要存在任何 CLAUDE.md，AGENTS.md 就被整个忽略。所以跨工具的标准做法不是玄学，是两行字的事：规矩正文全写在 AGENTS.md 里，CLAUDE.md 就留一行 @AGENTS.md。

我自己的内容系统账号就是这么配的：CLAUDE.md 打开只有那一行，AGENTS.md 才是正本。一份规矩，多种工具共读，不用抄两遍。

对你现阶段的意思：只用 Claude Code，一份 CLAUDE.md 干净利落；项目可能被别的 agent 碰、或者你就是不想维护两份，就上面这个两文件套路。

写你自己的

你的项目现在也有文件夹、有 git、有远端家了，该给它立规矩了。四段照抄：这是什么（两三行）、硬规矩（你的绝对不）、命令（怎么跑起来）、不要做。

从零开始的话，头五条规矩往往是你已经撞过或想过的事：不收费买字体、页脚署谁的名、要不要 Analytics、能不能上框架。写下来，哪怕只有四行。

规矩会越来越多，别把 CLAUDE.md 撑肿——它得短到一屏看得完才管用。厚的部分拆出去，主文件一行 @docs/design.md 就能把那页拽进来，AI 用得到才深入，这就是渐进式加载。我自己的内容系统整个就是这个结构：进门一页纸，上面一张表写着"做什么读什么、什么不许读"，你以后会撞见同款。

跟做步骤

1. 在项目文件夹开新会话，先问："如果我想加一个功能，这个项目的规矩和限制是什么？"——存下这份含糊的答案 2. 在项目根写 CLAUDE.md，四段格式，先 5-8 行 3. 关掉，再开一个全新会话，问一模一样的问题 4. 对比两次答案：第二次应该开始引用你写的原话 5. 以后每撞一次它越界，回来给宪法补一条——这文件是养出来的，不是供出来的

及格标准

新会话里问"这个项目有什么规矩"，它答出来的内容能对上你 CLAUDE.md 里的硬规矩原句。从"它猜"变成"它有出处"，就及格。

卡住了

  • 写了没生效：CLAUDE.md 必须在项目根目录，且会话要在该目录启动；改完内容开新会话再试。
  • 它还是越界：多半是你写得太空。"保持轻量"拦不住任何东西，"不许引入构建工具和框架，全部原生 HTML/CSS"才拦得住。每条自检一下能不能判真假。
  • 越写越长：砍。把长规矩挪进单独文件，主文件留 @引用。一屏是上限。
  • 不知道写啥规矩：等式——你上次心里嘀咕"它怎么这样"的那件事，就是头一条。

轮到你了

现在给你的项目想两三条"代码说不出"的绝对不，写进宪法。它们平时看不见你，下一次新会话，它们会替你把住关。
