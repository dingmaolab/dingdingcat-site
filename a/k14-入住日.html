第14课｜入住日：买个域名，把网站挂上公网

上手课 · 第 14 课 · 2026-11-21

先把丑话说在最前：这一课的正文写完了，但入住还没发生。 域名没买，Pages 没开，四个关键位置在正文里明晃晃留着【待填】。

为什么敢这么交？上节课刚学的：没发生的事不能写成发生了。入住日这种要花钱、要等审核的课，要是把攻略写成游记，那这门课讲了三遍的"只写实测的账"就成了笑话。所以今天你看到的是一篇带着施工孔的课文——事实面全部核完，体验面等真住进去补。这也是给读者的预告：跟到这一课的人，会看着我现场办入住。

本课目标

  • 想明白"租的门牌"和"自己的门牌"差在哪
  • 拿到一份当天核实过价格的域名决策表（2026-11-21，阿里云）
  • 抄走入住流水线：建仓、开 Pages、买域名、接 DNS，四件事的正确顺序

概念卡

  • GitHub Pages：GitHub 白送的静态站托管。你仓库里的 html，它给你发布成网页，https 都包了。
  • 子域名（借门牌）：不花钱也有地址——你的用户名.github.io/仓库名。能用，但那是挂在别人名下的门牌，搬家就作废。

— 正经域名（自己的门牌）：按年付费租下来的短地址，比如 xxx.cn、xxx.com。严格说域名都是"租"的（注册制），但续费在手，别人搬不走你。

  • DNS 解析：把门牌号翻译成机器找路的地址。你买域名那一刻拿到的是"改登记的权利"，接 Pages 就是把登记指向它那四台服务器。

门牌对比：为什么说入住是个仪式

借门牌的地址：qiluluai.github.io/dingdingcat-site——长，念不清，名片印不上，别人记"github 后面那串"。 自己的门牌：xxx.cn 六个字母，微信里发出去对方一眼读完。

技术上两者内容一模一样，差的只有一件事：这是谁的房子。 网站做到这一步，值不值一个每年几十块的门牌钱，就是这一课要你拍板的。我的答案是值——一个能被记住的地址，是"个人站点"从玩具变成资产的临界点。

行情与选择（2026-11-21 当日核价）

先纠一笔旧账：这门课建号时写的"域名一年 30-70 元"，行情变了——阿里云 11 月 1 日起 .com 调价：注册 90、续费 99/年（双 11 活动价 76）。.cn 仍是老实的便宜档：注册约 38、续费约 42，活动能压到 30。

三条路，账先摆平：

1. .cn 一条腿（推荐入门）：一年四十来块，"一顿饭零头"的承诺照旧成立。缺点：部分老外设对 .cn 的输入联想不熟。 2. .com 一条腿：更通用，一年 90-99。名字短的话值。 3. 两条腿：.cn 当主门牌，顺手 38 元把同名 .com 也攥手里重定向——防御性买法，一年 130 上下。

命名口径（给读者的，也是给我自己的）：短、能口播、不带连字符、别蹭商标。我的候选已经列进素材账，定名 dingmaolab.top：whois 直查注册局确认无主才下的单。信息模板当天提交当天过，serverHold 解除只花了一顿晚饭的功夫。。

还有个 7 月新规别踩：阿里云账号本身要先实名，才能新增域名——账号实名一次，域名实名走"信息模板"（身份证照片，审核 1-3 个工作日，常见当天过）。模板没过的域名是 serverHold 状态：买了，但解析不生效。"我的域名打不开"的头号原因就是这个，不是玄学。

入住流水线（正确顺序，附我的施工孔）

第 0 步，先有站点仓库。 域名是门牌，仓库才是房子——第 4 课那发 git push 还没落地的，先回去补。回执在案：用户在 github.com 亲手建 dingdingcat-site（先私有起步，见彩蛋反转），命名空间 dingmaolab；本地 site 仓把分支从 master 改名 main，git remote add origin 后 git push -u origin main，输出 * [new branch] main -> main，复核 ls-remote 与本地 HEAD 一致——七发历史一夜上云。

第 1 步，开 Pages，住进临时门牌。 仓库 Settings → Pages → 选分支 → Save。几分钟内 用户名.github.io/仓库名 能打开。此刻你的网站已经在公网上了——买域名只是换门牌，不是从零开始。借门牌 dingmaolab.github.io/dingdingcat-site 亮起，几分钟后它光荣退休——GitHub 把借门牌的请求 301 去了新门牌，那是「网站有主了」的信号。

第 2 步，买域名，等实名。 万网查询 → 加购 → 建信息模板 → 付款。然后等审核，这期间干什么都行，就是别改解析。金额作者发话从略（续费 39/年 的零头，不值得细账）；审核当天过。

第 3 步，接上。 两条路按习惯选：

  • 裸域名（xxx.cn）：加四条 A 记录，值依次是 185.199.108.153 / 109.153 / 110.153 / 111.153
  • 带 www：再加一条 CNAME，值 用户名.github.io

仓库根目录放一个 CNAME 文件写上你的域名（或者在 Pages 设置里填），Pages 才认这块牌。五条记录（四 A + www CNAME）填完，十几分钟 http://dingmaolab.top 返回 200；证书比预告的快，回头复测时 https 已经通了，Enforce HTTPS 那个勾都显得多余。

第 4 步，锁 https，办暖房。 DNS 生效后回 Pages 设置勾 Enforce HTTPS，用 https 打开一遍；再回微信里发给自己点开——这一条的实测结果留给第 15 课的可达性表，先如实挂账。

入住仪式： 把新链接发给第一个人。不用配文案，发出去那一刻这门课的前半段就算毕业了。仪式还没办。链接已经能打开，作者手里攥着它还没发给任何真人——按这门课自己的规矩，这一格就空着，留给晨审那天的头一声「你打开看看」。

备案的门，今天说清

国内服务器的规矩是"先备案后开门"，但 Pages 是境外托管——这条门牌不需要备案，也不归备案管。天下没有白住的房子，代价是另一张账单：境外服务在国内网络的可达性不保证，微信内打开时好时坏是常态。这门课的处理方式是第 15 课拿真数据说话，打不开搬家（第二季）就是预案，不算失败。到时候如实报。

跟做步骤

1. 站点先推上 GitHub、Pages 打开——用借门牌确认"网站已经活着" 2. 想三条备选域名（短/可口播/无连字符），查 .cn 和 .com 当日价，按预算拍一条 3. 账号实名+信息模板办好再付款，付款后等模板通过，别急着解析 4. 按上面第 3 步接 DNS，仓库放 CNAME 文件，等生效 5. 勾 Enforce HTTPS，手机浏览器、微信各打开一次，截图存进你的档案

及格标准

手机浏览器地址栏里手打你的域名，https 打开的是你的网站。到此即入住。加一条仪式性的：链接已经发给了至少一个真人。

卡住了

  • 买了就打不开：九成是实名/serverHold，模板状态没显示"成功"之前，解析配了也白配
  • 配好 A 记录还是 404：仓库侧 CNAME 文件或 Pages 设置里的域名没填——门牌和收件地址两边都要写
  • https 按钮是灰的：DNS 还没全球生效，等；生效判定可以用 nslookup 你的域名 看是不是那四个 IP
  • 微信里转圈：境外托管的现实，先记下现象和时间，这就是第 15 课的原始素材，别慌着自我怀疑

轮到你了

入住完成，房子有了、门牌有了、钥匙在手。下一课把最后两块装上：谁来过、打不打得开——以及给整门课算一张三栏总账。

入住日彩蛋：上线把三条陈账炸了出来

网站真上线的那一个多小时里，三件事接连找上门，都值得记进「发布日的真实模样」：

一，拍板稿没住在真站里。 作者点开刚上线的站：「UI 怎么不是我拍板的那个，logo 也是。」——对。此前几轮的视觉决策（月白底、红猫皮 D 之眼、Lab 斜体、侧抽屉）全落在原型文件里，真站的生成器还穿着建号那天的旧皮。刷颜色补不了架构的漂移，最后把整套模板从拍板稿移植进 build.py 才算数。课上刚讲「门面不许许愿」，转头发现整个站的外观本身就是一句许愿。判据从此加一条：每次设计拍板，问一句真站同步了吗。

二，上午修的 bug 下午复发。 文章页里点导航 404——死链扫描上午刚抓过修过（../ 基准路径），下午重写模板时把 base 参数弄丢了，同一个坑二次落地。修复之后，死链扫描升格为每次动模板必跑的回归项。回归回归，回的是自己种下的过去。

三，一个从未存在的系列下架了。 有人问「讲清第一课跟课 1 是不是重复」——查证：那个系列从未开课，架上那本 17 行的小册子是旧教案的边角。撤下、归档、不塞进任何栏目凑数；顺手给生成器加了孤儿清理，文章下架时残留页面自动扫掉。系列的存在以第一篇真货为前提，书架证明不了内容。

这三条有个共同点：都是「上线」这个动作逼出来的。没上线前，漂移是感觉，回归是运气，虚设是设计——上线之后，它们统一变成 bug。
