第8课｜把 UI 定下来：AI 能出四十张，你只要答三个问题

上手课 · 第 8 课 · 2026-11-21

这一课的内容，就是今天我自己刚跑完的一场马拉松：网站从排版到 logo 到头像，AI 出了四十多张图，最后定下来的东西，被我自己否了三轮才活下来。

回头看，整场马拉松里 AI 干的是活，我干的只有三件事——三个问题。每个问题出口，方向盘就拐一次。这一课不讲配色理论（我不懂，你也不用懂），讲的就是这三个问题怎么问。

本课目标

  • 看懂 UI 环节里人和 AI 的分工：AI 负责出量，人负责给判据
  • 学会正确的过问顺序：先盘内容，再排架构，后谈长相
  • 学到三个可以抄的问题（今天每个都值一次返工）

概念卡

  • 内容盘点：先数清楚你到底有几种东西要放上去。课程是课程、散装文章是散装文章、图文是图文——物种不同，住的房子就不同。
  • 信息架构（IA）：东西分几页、每页管什么、入口怎么排。它在长相之前，是 UI 的地基。
  • 设计锚点（token）：颜色和字体规则集中成几个变量，全站只引用变量。以后"换皮肤"就只是改变量值。

第一条线：页面

上午我给 AI 的指令很外行："给网站出几版 UI。"它很配合，出了四版排版：课表流、时间线、双书架、feed 置顶。都能看，信息架构也对。

我盯着看了半天，说不出哪里不对，只憋出一句："还是在主题下变排版。"

这句话把病根炸出来了。AI 不是设计不出好看的东西——是我们从没告诉它这站承载什么。公众号要发热点快评、实测、随想、图文，这些和"十五课连载"是完全不同的物种，可我们的方案里只有一位"课程游客"的座位。物种没点清，长相当然只是在换桌布。

于是回到纸上重做：内容盘点（四个物种）→ 页面清单（七类模板）→ 每一页去找一个具名的业界参照物（课程详情页=极客时间的章节流、文章档案=Substack 的时间线、正文页=Tufte 的边注）。做完这三步，课程详情页的高保真一版就过了——因为每页该长什么样，早有答案，AI 只是照抄成熟的行业经验。

顺手交代一个彩蛋：那晚我还烧了一个生成器脚本，五个页面模板 × 四套颜色参数包，一次跑出二十个完整网站。当时只当玩，后来它成了"换皮肤只要改变量"的实物依据。写代码这件事，在 vibe coding 里经常是这样：先跑通，再懂它值多少钱。

第二条线：文案

下午审生成的页面，一行小字把我噎住了："双周一更 · 已发布 7 课 · 公众号首发"。

哪来的双周一更——我们一篇都还没发。这个 cadence 是建号那天写在自己规划文件里的目标，AI 把它当事实抄上了门面，顺手还把"已发布 N 课"的假账也做了。

"为什么要写双周一更之类的……"我问出这句话的时候，其实是在问 UI 里很深的东西：页面上一切句子都是承诺，承诺必须是已发生的事实。 更新频率、首发阵地、数字统计，全都要么实测、要么不写。

全站扫了一遍，这些词从二十四个文件里清了个干净，并且当场变成一条验收：以后每次施工，"承诺词 grep 必须为零"。文案也是 UI——这大概是这门课里"只写实测的账"这条老规矩，第一次以这么具体的方式收费。

第三条线：标识

轮到猫本身。让 AI 画 logo，第一轮八个方向：几何猫脸、负空间猫、铃铛猫……我给的判词是不客气的一句："卡通，没有设计感。" 第二轮上了概念（双关、负空间、圆规构建线），第三轮直接叫来生图模型连烧四十一张：包豪斯红猫、渐变色团、霓虹线框、粒子星尘、换三套配色……

看着挺败家，但每一轮都靠一句话省下来：

  • "感觉不可爱"——可爱派整支淘汰，不用纠结
  • "科技未来一点呢"——试完，确认自己不要
  • 烧完一圈四十多张之后，最后指着最早那张最简单的 D 字标说："这个感觉还简单一点。"

四十张图的旅程，终点是出发的地方。但这一圈不是白烧的——它把"简单是你的根判据"这条信息，从我的直觉变成了写进规范的账。现在这个站的规矩：主标=D 之眼，三套皮肤（月白/金墨/红猫），换装=改三个锚点值；头像用夜皮，页头用红猫皮，全部进了 git。

三个问题，抄走

1. "是不是只在主题下变排版？"——AI 出 N 版但你觉得都差点意思时，八成不是它画得差，是内容盘点和架构没做。回纸上。 2. "这句话是事实，还是目标？"——页面上每个数字、每个频率、每个"首发"都过这一刀。文案即承诺。 3. "在所有尝试里，哪一个最简单？"——绕一大圈之后敢回到最初那个，不叫白忙，叫交学费买了判据。

你不需要会设计。你只需要在这些时刻，敢对自己的不满意说出原话。AI 出量，你出判据——这就是 UI 环节里人干的活。

跟做步骤

1. 动手前先盘点：把你的内容按物种数一遍（连载/单篇/图集/关于），每个物种一句"读者对它做什么" 2. 给每个物种定一页职责，每页找一个你真心觉得好看的具名网站当参照，贴链接进方案文件 3. 让 AI 按方案出高保真，你的反馈只许说具体感受（"不可爱""信息太密"），不许硬憋专业词 4. 定皮肤锚点：让 AI 把颜色字体收成变量写进规范，以后换皮=改变量 5. 审文案：全文搜"更""首发""已发布"这类词，逐条问是不是事实，不是就删 6. 定稿方案+清单进 git——第 9 课的药，这课先吃一半

及格标准

你的项目里有：一份内容盘点、一个每页挂着具名参照物的方案、至少一处"被你说破后修正的文案"。三条都有，UI 这关你就真过了——过没过跟好不好看无关，跟账有没有理清有关。

卡住了

  • 说不出哪里不对：用今天的原话，"是不是在主题下变排版"。说不出判据时，先怀疑层次（架构？内容？），别硬夸或硬骂。
  • AI 狂出图刹不住：给它立规矩——每轮最多三张，每张配一句它自己的设计意图。量大不交判据，等于白看。
  • 审美心虚不敢否：你的不满意就是需求。今天那句"卡通，没设计感"，值十轮修改。

轮到你了

下一课是这套流程里我最想让你抄走的一页：方案和任务单——动手之前，先谈好"改起来多贵"。今天这三个问题问出来的所有账，最后都会变成那张两页纸的施工单。
