第13课｜需求会变，规格不能断：日常三步，发布前一查

上手课 · 第 13 课 · 2026-11-21

先交代这课的特殊性：下面那个"我"，是账号主人；写作用的是他和 AI 结对——谁的手敲的字不重要，谁拍的板才重要，这也是本课的内容之一。

然后说件丢人的事。今天写这节课写到最后，派了一个毫不知情的 AI 通读全篇做发布前校对。它交回来的报告里，最重的一条是：

这篇教人"承诺词零容忍、数字对实物"的文章，自己把"本课已通过全部检查"写在了检查完成之前。

它说得对。我当时确实还没等校对跑完，就在正文里宣称四道检查全过了。这份报告现在整个躺在同目录 校对13.md 里，正文的这一节就是它的整改记录。这节课不是教程配案例，这节课本身就是被教程救下来的一次事故。

本课目标

  • 把"改需求"从事故变成流水线：动代码之前，先动哪几页纸
  • 让规矩带着"案发现场"活着：每条为什么存在，可查
  • 抄走一张发布前检查单，包括那七个能让 AI 校对你的问题的原文

概念卡

  • 规格（specs）：这项目"要什么、不要什么、怎么算好"的全部书面决定。在这门课里就是三页纸：任务书（课 7 烤出来的需求）、方案（课 9 谈定的架构）、清单（课 9 拆出的施工包）。谁改了现实，谁就得回来改纸。
  • 活维护：规格跟着现实变，且每次变化留痕——追加、批注、commit，而不是重写、覆盖、散落。
  • 检查单：每次"要发出去"之前固定跑一遍的那几步。它的头号原则：单子上每样东西，跑没跑完，看证据，不看信心。

第一步：改需求，先改纸，再改码

今天下午的活例。文章写到一半，作者过来说：「文章是文章，微信的图文是独立的，2 个。」——网站要承载的内容，从四类变成五类（课程、单篇、图文、元信息，外加新分出来的"文章/图文"两兄弟各归各家）。

本能是伸手改代码。停。今天的实际顺序：

1. 方案文件追加一段"定稿增量"：物种清单、页面增减、导航扩到五项。原来的推导一个字不删——那是地层 2. 施工清单新增一包，验收写死："两页互不混排；空列表有兜底文案" 3. 然后代码才动，一个 commit 收口

任务书呢？它没被改——这次变更没动"为什么做"，只动了"怎么归置"。改哪页纸，取决于变的层级：想法变了改任务书，做法变了改方案，拆法变了改清单。三层纸，各管各的账。

顺序反过来的项目我也见过：代码先改完，纸"回头再补"。回头？没有回头。三个月后没人说得清图库页为什么单独一页——决定从"规格"降级成了"古迹"。

（一句点破：这一步依赖 git 存在才成立。把它讲在头个位置是事故叙事的需要，实操顺序看"跟做步骤"。）

第二步：规矩会被质疑，被质疑说明它在岗

今天诞生了两条规矩，各带着自己的案发记录：

规矩一：门面不许许愿。 下午作者扫首页，眉头一皱："为什么要写双周一更之类的"——查，那是建号那天的内部目标，被 AI 当事实抄上了台面。全站 24 个文件清扫，写进项目规矩文件（就是第 6 课那页 CLAUDE.md，给 AI 的厂规）：chrome 层零承诺词。chrome 指页面的"门面件"：导航、页脚、统计行——不是那个浏览器。傍晚死链脚本顺手复查，命中两篇课文正文，一查是课文在引用这句反面案例当教材——条款当天细化成"禁的是门面许愿，不禁正文讨论"。这条规矩的完整生命史，在 commit c75b7f2（立规）和今天下午的清单批注里。

规矩二：文案终稿权在人。 简介句被我"顺手优化"——加空格、拆词、缀了句口号。作者本人丢回一句原话，回滚。commit 消息里我自己记了自己一笔"越权改写"：6201ef6。

一条规矩从质疑里生、在误伤里细；另一条从越权里生、在回滚里立。规矩文件的理想形态不是法律条文，是判例集——每条后面带着案发现场，后来的人才知道它为什么长这样，才不敢轻率改它。

第三步：版本纪律，从我盖掉的旧稿说起

两条铁律，都是学费：

头一条：改之前先有 git。 今天最丢人的发现：这个账号的内容目录（方案、清单、十三份讲义、品牌图）直到今天下午才 git init——写"规格保养"课当天，查"版本纪律"素材，敲出 fatal: not a git repository。更疼的是随即想起旧案：第 5 课换方向后，新稿直接压在旧稿上存盘，第一代正文盘上查无死无对证，只剩旁边一个冻结的旧项目目录当墓碑。方向作废就标冻结、不删除——这条今天补进规矩，代价是已经丢过一版。 顺带理清仓库关系：代码和内容的历史是两种历史，分两个仓库。 站点仓（第 3 课建）今天走了四发：P1P2 施工、分家、文案终稿、修死链；内容仓（今天下午才开天）此刻你正在读的这页纸，初稿和修订版就分别是它头几发 commit——f179ddd 存了被校对砸之前的原样。这课正文改了什么，翻 commit 便知，包括那句被砸的谎的原句。

第二条：commit 消息是写给三个月后的自己的证词。 "P3+P4 施工"这种消息一文不值，"首跑抓到 50 条断链，文章内点主页即 404"这种才值钱——它就是案发现场。

第四步：发布前一查，以及它当场抓到的我

每个要发出去的成品，过四道闸。清单本身比流程重要，我把本课的完整跑法连证据摊开：

一查，机器闸。 写作工具自带的两个检查：一个查违规和编造嫌疑（错字、绝对化用语、无来源硬事实），一个查文字的"机器味"。本课初稿被逮两个 blocker——包括一处序数措辞被词表误伤，按系列口径换成「头」字族解决。

二查，链接活。 文末每条链接现场请求一遍，返回 200 才许上稿。死链不上稿，第 8 课立的规矩。

三查，数字对账。 正文里每一个 commit 号、文件数、耗时，对着实物念一遍。本课在这一查里改掉了"全天五发一条链"的错误说法——那是把两个仓库的历史缝成了一串。

四查，零背景读者。 派一个没参与过任何施工的 AI，只给这篇稿，问它七个问题。清单在这，可以抄：

1. 哪些句子需要读者自带背景才读得通（具体到行） 2. 哪里逻辑断层、跳跃 3. 有没有把"目标/愿望"写成"已发生事实"的句子 4. 结构顺序合理吗，"跟着做"能照做吗，缺什么前置 5. 标题承诺和正文兑现对不对得上 6. 用一句话复述这篇在说什么 7. 只挑最重要的一个改进点

本课的第四查交回 15 条发现，最重一条开头已引。裁决结果：采纳 13 条、部分驳回 1 条（叙事顺序问题，实操顺序已在跟做栏纠正）、整改全部落在你现在读的这版里。这一查为什么最不该跳：前三查都在问"我按规矩做了吗"，只有它在问"我以为自己讲清楚了，真的吗"。 作者是自己文章里眼神最差的人，这课写到最后一天，信更实了。

跟做步骤

1. 今天就把你的内容目录 git init（没有方案清单文件？现在各建一页，标题就叫"方案""清单"，哪怕第一版只有五行——纸先存在，纪律才有宿主） 2. 下一次需求变更，按"想法→任务书 / 做法→方案 / 拆法→清单"找出该改的那页纸，追加不覆盖，然后才动东西 3. 规矩文件每加一条，后面半句为什么（"双周一更：目标被当事实，门面禁承诺"） 4. 抄走上面四查做成你自己的检查单，每次跑完在单子上标日期；用不了专业工具的，一查降级成"念一遍找绝对化句式"、三查降级成"每个数字对着实物念" 5. 发布前，把那七个问题原样发给一个全新会话的 AI，报告落盘，逐条裁决，裁决表跟稿同存

及格标准

你的内容目录里有 git 历史；方案文件里有"追加的增量"而不是"重写的一版"；最近一次发布留着带日期的检查单，和一份被采纳或被驳回的读者报告。三样齐了，你的规格就是活的——而且你已经有资格嘲笑今天下午的我。

卡住了

  • commit 觉得琐碎：消息按"证词标准"写——三个月后的你能不能只凭这行字想起当时为什么。写不出这种消息，说明这活本来不值得单独一发
  • 规矩越长越没人读：规矩也过四查。念每条判两句：能判真假吗？知道它为什么在吗？答不出的删掉
  • 读者报告太打击人：把它当第 4 查而不是期末考试。它挑得越狠，发布后被打脸的概率越低，这笔账怎么算都值

轮到你了

规格会养了，检查单在手了，下一课只剩那一下：买域名，接 GitHub Pages，把这一切挂到公网——入住日，你的链接第一次能被任何人打开。那天用的，还是这四查。
