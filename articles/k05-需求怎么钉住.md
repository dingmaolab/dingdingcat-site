这节课讲三家工具，它们治的是同一种病：你脑子里想法还是糊的，AI 已经急着开工了，做完你一看——不是我要的。三家的办法是一个方向的：**开工前，让 AI 先把你的问题问透。**

先交代本文的顺序，方便各取所需：第①节说为什么三家先学最轻的那家；第②节一行命令装好；第③节十分钟跑完你第一轮被追问；第④节讲三家分别什么场合用、什么场合别用；第⑤节是进阶经验加一张速查表。急着上手的，现在就可以跳去②③。

## 本课目标

- 装上第一个第三方工具包，并确认装成功了
- 跑通一次 grill-me 的追问，知道它是怎么一轮一轮问的
- 说得出 grill-me / OpenSpec / spec-kit 各自什么时候用

## 概念卡

- **skill（技能包）**：一页写给 AI 看的做事规矩，放在一个 SKILL.md 文件里，AI 遇到对应的事就照它办。第 1 课那张因果链里的"规矩"，说的就是它。
- **插件（plugin）**：Claude Code 官方的分发打包方式——把一批 skill 捆在一起一次装好，之后自动更新。

## ① 为什么先学最轻的一家

先认一下这三家，各用一句话：

- **grill-me**：什么文件都不写，就是按着一棵决策树（把你的想法拆成"需要一件件定下来的问题"清单）不停问你，问到你自己想清楚为止。
- **OpenSpec**：你们聊清楚的东西会变成一叠文件——每个功能开一个文件夹，里面放着"为什么做、要求是什么、打算怎么做、分几步做"四份文档。
- **spec-kit**：更彻底，把"给项目立原则、定需求、出方案、拆任务、执行"整条流程做成了一套命令。

![课5三家定位图：用完之后各留下什么——grill-me 什么都不留，OpenSpec 留一批文档，spec-kit 留一整套流程](课5三家定位图.png)

（星数只当人气看，都是一手仓库实测：合集 32.9 万 / OpenSpec 7.5 万 / spec-kit 15.1 万——三家都不是小众玩具。）

为什么从 grill-me 开始？因为它最轻——不用你先学任何新东西：不装新目录规矩、不建文件夹、问完不留一地文件，你对它的全部操作就是回答问题。还有个实际原因：另外两家其实都把"想清楚"当前提——OpenSpec 的 proposal、spec-kit 的 specify，写之前你总得先知道自己要什么。先问，永远是第一步。

## ② 装上：一行命令

在终端里跑：

```
claude plugin install mattpocock-skills@claude-plugins-official
```

**装没装上，怎么确认**：跑一下 `claude plugin list`，应该能看到 `mattpocock-skills@claude-plugins-official` 这一行，后面跟着 `Status: ✔ enabled`。我 11-21 实测到的版本是 v1.3.1，你的可能更新了，正常——插件默认自动更新。

一个官方提醒值得当回事：这套 skills 还有一条走 skills.sh 的安装路线，**两条选一条就行**，都装会让每个技能出现两遍。

## ③ 第一次被追问：十分钟版

**新开一个会话**再开始（官方建议：别在已经聊了很多方案的旧会话里问，它会顺着旧思路问你）。输入：

```
/grill-me 我想给网站加一个教程路径页
```

接下来发生的事，和"AI 随口问两句"完全不一样。它把你的想法拆成一棵决策树，然后**一轮一轮地问**：每一轮，把所有"现在就有条件问"的问题一起端出来——每个问题编着号，底下跟着一条它建议的答案（问题故意这么措辞：你回答"行"，就等于采纳了它的建议）。

![课5示意图：第一轮同时问出三个问题，每个都带一条推荐答案；你答完，又解锁了第二轮两个新问题；还有一个问题要等前面的答案，被留到了后面](课5轮次frontier图.png)

你答完这一轮，你的答案又解锁了下一轮的问题。它有条讲究的原则：**依赖你还没给出的答案的问题，绝不提前问**——所以每一轮你答的都是"现在真能定的"。

什么时候算问完？该问的都问完了，没有哪个要紧的问题被悄悄跳过。问完还有一条很讨喜的规矩：**你没说"我们想清楚了"，AI 不会动手写一行代码。**

（顺带交代：第 7 课那场实录里我是一题一题问的——同一棵树的另一种走法，节奏舒服就行，逻辑没变。）

## ④ 什么时候用它，什么时候别用

| 用它 | 别用 |
|---|---|
| 做一个新功能，动手前想钉目标 | 你已经能写出精确的规格——官方文档的意思：写得清，就不用问了 |
| 方向、定价、选题这类要人拍板的事 | 有些问题嘴上答不出来，比如"这个页面该什么感觉"——先做个一次性的小样看看，回来一行就能答（官方给这类问题起了名：ungrillable，答不了就去做，别硬聊） |
| 一篇拿不准角度的文章——官方明说它不限代码 | 用 grill-me 之前先把 plan mode 关了。官方理由很实在：plan mode 会让 AI 急着交出一份计划，而这一刻你要它继续问 |

这族其实有三兄弟，按场合挑：**grill-me**，任何事任何地，不碰你的仓库；**grill-with-docs**，需要跟代码库对齐时用——它会读码，还把学到的东西写成术语表（GLOSSARY.md）和决策记录（ADR），这兄弟是会写文件的；**wayfinder**，一件事大到一个会话装不下时，先画一张地图——把要定下来的小事一件件列上去，再逐个问清楚。

## ⑤ 进阶与参考

**最常见的失败是被动。** 官方文档专门点名了一种假高效：四十个问题你一路答"同意"，结束时手里拿着一份 AI 写的计划，你只是一路点头——你没做任何决定，产出却显得比实际笃定。正确的姿势是掌舵：问得太浅就顶回去，范围漂了就喊停，不知道就答"不知道"，而且是认真的。**结果的质量取决于你答案的质量，不是问题的数量。**

**聊完了想留个书面结果怎么办**：grill-me 自己是不写任何文件的（官方原文 "It writes no files and leaves no workspace behind"），它的产出就是你脑子里那版想清楚的想法。想要文档，同族里接好了手——**to-spec**：它不再提问，直接把这段对话综合成一份 spec，投到项目的 issue 里。顺序故意是反的：**先共识，再文档**——先想明白，再落笔。

**三家速查**（安装和用法全部出自各家官方文档）：

| | grill-me | OpenSpec | spec-kit |
|---|---|---|---|
| 装 | claude plugin install …（Claude Code 官方插件市场） | 官方 curl 脚本 / npm / brew，装完进项目跑 `openspec init` | `uv tool install specify-cli`，然后 `specify init 项目名 --integration 你的agent` |
| 用 | `/grill-me` + 一句想法，一轮轮答到问完 | `/openspec-explore` 边聊边想；或 `/openspec-propose` 直接开 change 文件夹 | `/speckit-constitution` 给项目立一次原则，之后每个功能从 `/speckit-specify` 起步走命令链 |
| 用完留下 | 零文件 | 一叠可追溯的文件 | 项目原则 + 逐功能的文档 |
| 适合 | 想清楚再说 | 单人也要留档 | 要整套流程仪式 |

## 跟做步骤

1. 跑 ② 的命令，`claude plugin list` 看到 `enabled` 再往下
2. 新开会话，`/grill-me` 加一件你真要做的事，老实答完第一轮
3. 对照 ④ 的表，想清楚你那件事该用三兄弟里哪个（多半就是 grill-me）
4. 问完后把那些决定用自己的话复述一遍，让 AI 核对有没有理解偏——对了就算达成共识，这份共识就是第 7 课的开工材料
5. 想要纸面结果的，试试同插件里的 to-spec

## 及格标准

`claude plugin list` 里那行 enabled 你亲眼见过；并且你回答过至少一轮"带推荐答案的编号问题"——你说"行"的时候，清楚自己点头接住的是什么。

## 卡住了

- **/grill-me 没反应**：先回头确认 enabled；确认了就换个新会话再试，技能清单是会话启动时读的
- **它问得太顺，你一路在答"同意"**：停——你正在踩 ⑤ 说的那个坑
- **你要的其实是文件不是对话**：那该用 OpenSpec，照 ⑤ 的表换家，不用恋战

## 轮到你了

下节课网站要添一个新物种：把需求画成界面。你会看到同一套"先问清楚再动手"在 UI 环节原样运转——而 grill-me 今晚已经在你机器里，别让它吃灰。
