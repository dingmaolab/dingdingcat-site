上一课你在 diff 里看清了 AI 改了什么。看清是一回事，下一个问题更实际：看清了，觉得改坏了，怎么办。

你大概率会想按 Ctrl+Z。没用。那是编辑器里的撤销，AI 在它自己的会话里做的改动，根本不进你的撤销历史。你把文件存了、把编辑器关了，刚才那一按就再也按不回来了。

真正的后悔药不是撤销键，是 git。

## 本课目标

- 学会 git 的三个动作：存、看、退
- 把你的项目文件夹从"不敢让 AI 改"变成"随便改、改不坏"
- 亲手改崩一次，再亲手救回来

## 先认识 git

说专业点，git 是一个**分布式版本控制系统**。它追踪文件内容的每一次变化，把每个版本完整记下来。它不存"改了哪几行"的差异，而是直接给整个项目拍快照，再用一串叫 SHA-1 的校验和给每张快照编号，确保内容没被悄悄改坏。"分布式"是说，每台机器上的仓库都藏着完整历史，不依赖哪台中央服务器。

这东西的来历有点意思。2005 年，Linux 之父 Linus Torvalds 亲手写了它。起因是 Linux 内核社区原本用一个叫 BitKeeper 的商业工具管代码，那年授权闹掰了，没得用。Linus 干脆自己造一个，要求快、能管几千人的大项目，没多久就写出了能用的雏形。

如今它已是软件开发的事实标准。几乎所有项目都用它管代码，GitHub、GitLab 这些平台整个建在它上面。程序员日常离不开它——不是因为要背命令，是因为它给了人"随便改、改不坏"的底气。

落到我们这一课，你只需记住一个比喻：**commit 是存档，restore 是读档**。玩游戏的人都懂。git 就是给代码做存档读档的工具。

再认几个词，跟做时够用：

- **仓库（repository）**：装了 git 的文件夹，多一个隐藏的 `.git` 目录，快照都存那。
- **工作区**：你正在编辑的文件。
- **暂存区**：你挑出来、准备放进下一张快照的改动。`git add` 就是把改动放进暂存区。
- **提交（commit）**：把暂存区的内容拍成一张快照，定格成一版。

认识这些，就可以动手了。

## 实跑记录

我在自己的网站项目里，把这三个动作完整走了一遍。你在课 2 那个放了 hello.txt 的文件夹里练，是一回事。

### 存档

先给项目拍一张快照：

```
git init
git add index.html
git commit -m "第一个页面：个人主页"
```

`git init` 把文件夹变成仓库，`git add` 把文件放进待存区，`git commit` 真正拍下快照。我跑出来的结果：

```
[master (root-commit) 58a3f4b] 第一个页面：个人主页
 1 file changed, 77 insertions(+)
```

那串 `58a3f4b` 是这张快照的编号。从此这一版定格了，怎么改都不怕。

想看存过哪些版本，跑 `git log --oneline`，一行一版，清清楚楚。

### 撞墙

提交的时候，屏幕上刷出一行警告：

```
LF will be replaced by CRLF
```

我当时心里一紧，以为坏了。查完才放心：这是 Windows 换行符的警告，不是错误。Windows 和 Linux 的换行方式不同，git 转换时提醒一声，提交照常完成。这一课你会在 Windows 上跟做，多半也会撞见它，撞见就知道：它是来打招呼的，不是来报丧的。

### 改崩

有了存档，就可以放心让 AI 下手。我故意让它把主页标题里"亲手做一遍"改成"随便搞搞就行"——模拟一次改崩。

改完跑 `git diff`：

```
-    <h1>...<em>亲手做一遍</em>。</h1>
+    <h1>...<em>随便搞搞就行</em>。</h1>
```

减号是原来的，加号是现在的。上一课的 diff 和这一课的 git diff 是同一个意思：改动摊开给你看。

### 读档

不满意？一行命令回到存档点：

```
git restore index.html
```

跑完再看 `git status`，干干净净。打开文件，标题回到了"亲手做一遍"。刚才那次改崩，像没发生过。

顺带一句版本门槛：`git restore` 是 git 2.23 之后才有的命令。太老的版本跑不出来，用 `git checkout -- 文件名`，效果一样。不确定的话跑 `git --version` 看看。

### 三招归拢

回头看，这一课就三招：

- **存**：`git commit`。满意了，拍一张快照。
- **看**：`git diff` 看改了什么，`git log` 看过哪些版。
- **退**：`git restore`。改崩了，回到上一版。

会了这三招，你就敢放手让 AI 改了。反正随时能读档。

## 本地和远程，先把两个名字分清

这一课玩的都是**本地**存档——快照存在你自己电脑的 `.git` 里。你这台电脑要是硬盘坏了，存档跟着一起没了。把存档托到网上去，是下一课的事。

还有个新手常见的混淆，先说清：**git 和 GitHub 不是一回事**。git 是你电脑上管版本的工具；GitHub 是把仓库托管到云端的平台，相当于给 git 存档安了个网上的家。一个管版本，一个管托管。下一课，我们就去把家安上。

## 跟做步骤

1. 在项目文件夹打开 Claude Code（就是你放 hello.txt 的那个），跑 `git init`
2. `git add .`，再 `git commit -m "工作台装好了"`（头一次提交让你设名字邮箱，按提示设一下就行）
3. 对 AI 说一句故意改坏的话，比如"把第三句改成一句瞎话"
4. 跑 `git diff`，看清它改哪了
5. 跑 `git restore hello.txt`，确认改动消失
6. 跑 `git log --oneline`，看到你存的档

## 及格标准

你亲手把文件改崩过一次，用 `git restore` 救回来了，并且 `git log` 里至少有一版提交。做到这个，git 的门你就进了。

## 卡住了

- **LF will be replaced by CRLF**：真跑撞过的警告，换行符差异，忽略即可，提交是成功的。
- **git restore 不存在**：git 版本太老（2.23 以前）。换 `git checkout -- 文件名`，或先升级 git。
- **提交时问你要名字和邮箱**：git 要个存档人签名。跑 `git config --global user.name "你的名字"` 和 `user.email "你的邮箱"`，填自己的就行，只存在你本机。

## 轮到你了

再故意让 AI 改崩一次，这次别急着读档——先用 `git log` 找到更早的存档点，试试回到那一版。体会一下"有存档"和"没存档"的差别，那种敢放手的感觉就是 git 给的。

你的存档现在只躺在这台电脑里。硬盘坏了呢？想给别人看呢？下一课，GitHub，给存档安一个网上的家。
